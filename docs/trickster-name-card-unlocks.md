# 捣蛋鬼出没玩家纪念

名片 ID 为 `special_trickster`，说明为“玩家纪念”。头像、静态卡面由游戏服务器提供；动态 GIF 仅作为可主动下载的 optional 个性化资源。未下载时显示静态图，下载后显示动图。

主服 `profiles.ready()` 在开放登录前运行 `authority.migrateTricksterNameCards()`。首次执行时，汇总当前账号、玩家档案、排位档案和历史档案中的真实 aid，去重后冻结名单，迁移键为 `trickster-existing-v1:20261021`。名单在任何发放之前写入排位存储顶层 `nameCardGrantSnapshots` 并 flush，再写入主服复制状态的同名字段。后续启动使用已冻结名单，不追加新注册玩家。

每个 aid 通过现有 `rank.nameCards` 事务写入 `unlockedNameCards` 和 `nameCardGrantMigrations`，使用现有 rank 复制字段同步到附服。已持有的“晴雨同汪”权限保留，两种名片分别鉴权。当前由附服持有写入租约的 aid 进入持久化 `pendingNameCardUnlocks`，交接后重试，名单不会改变。

新玩家不会因登录、排位结算、重启或复用旧名字获得本纪念名片。迁移入口只供进程内部维护，未新增浏览器接口或远程授予 API。仅更新 Win7 资源增量包不会执行服务器档案迁移，主服必须实际运行更新后的游戏代码。

## 上线次序与档案保护

1. 停止主服和附服，分别备份其真实的账号、玩家、排位、历史及复制状态文件；不要用开发机或测试环境的同名 JSON 文件覆盖线上档案。
2. 确认真实玩家档案已在主服可读后，再更新游戏服代码与头像、静态卡面，并安装 Win7 资源增量包。首次启动主服会冻结当时已有的 aid；如果先在空档案上启动，空名单也会被永久冻结，之后不能自动补发。
3. 核对主服日志中“捣蛋鬼出没玩家纪念发放”的 `total`、`granted`、`deferred`，并抽查旧玩家可选、新玩家不可选；附服待交接账号在复制同步后重试。
4. 部署时排除本地测试产生的 `ranked-profiles.json`、`profile-replication-main.json` 等持久状态文件；只迁移明确列出的代码、清单与素材。
